# StreamHarbor v0.26 — QA scope

Candidate only / NO_GO. Display-only host part-ordinal extraction in the browser action popup. The host's sequential `partIndex` and the currently open part yield the highest part number allocated by the running recorder in its current in-memory state; it is not the number of saved, verified, nonempty or decodable media files. It can be incomplete after recovery and does not provide a durable, separately validated session ledger. Video and separately recorded audio are shown independently. Host status is redacted in the extension background before reaching the popup, which continues to show only bounded last-100 part entries and the global export ledger.

No streaming algorithm, network access gate or storage writes were modified. Manifest version is still 2.56.0. New Node tests cover both browser message paths, 100+ samples, overflow, unknowns, old idle data, audio unavailable, UI and generated-copy parity. Real browser installation, live streams, 100+ actual media parts, long recordings, crash/recovery, storage quota and real A/V decode/sync are **not** accepted.
